# ZTEIST 商业模式与技术路线

> 版本：v1.0（2026-08-21）
> 依据：中友会 30 万人才池 + 出海服务生态 + MVP 技术设计
> 供 ZTEIST 项目 CLAUDE 参考

---

## 一、核心逻辑

**中友会真正的资产不是"数据"，是「信任 + 人才网络」。** 商业模式围绕这个资产，从"卖资格"→"卖服务"→"卖成交"逐级升级，客单价和天花板越来越高。

```
阶段一：会员费（卖资格）      → 客单价低，先验证付费意愿
阶段二：服务费（卖报告/分析）  → 客单价高，AI 差异化
阶段三：交易佣金（卖成交）     → 天花板最高，等生态成熟
```

## 二、阶段一：会员费（MVP，现在就能做）

### 收入模型

| 客户 | 定价 | 权益 |
|------|------|------|
| 大陆企业会员 | 1999-4999 元/年 | 发布供求/招聘、检索人才、基础对接 |
| 国内个人 BETA | 99 元/年 | 加入网络，过滤噪音 |
| 海外个人 BETA | $9.9/年 | 加入网络 |

### 支付架构（双主体 + 双通道）

| 客户 | 收款主体 | 支付通道 | 关键点 |
|------|------|------|------|
| 大陆企业会员 | 深圳公司 | 对公转账 + 微信/支付宝企业版 + **发票** | 企业要发票 |
| 国内个人 BETA | 深圳公司 | 微信 / 支付宝 | 99 元 |
| 海外个人 BETA | 香港公司（LEADING INTERNATIONAL） | Stripe 信用卡 | $9.9 |

> ⚠️ 支付隔离铁律：AIF 系（含 bilumora）走 AIF 的 Stripe，ZTEIST 走 ZTEIST 独立 Stripe，**互不代收**。代收 = Stripe 违规 = 冻结 + 连带封号。

### 技术支撑（已有 90%）

- 注册 + 结构化标签 + 邀请码 → 已建（`src/db.ts` 完整建表）
- 会员系统 + 支付 → 复用 AIF
- 搜索 + 隐私分级 → SQLite 已建表

### 目标

第一年做 100-500 家企业会员，验证"企业愿不愿意为出海人才网络付费"。

## 三、阶段二：服务费（报告/分析，AI 差异化护城河）

**这是区别于一般人才平台的地方——AI 自动生成报告。**

| 服务 | 定价 | 技术 |
|------|------|------|
| 企业背景报告 | 300-800 元/份 | 启信宝 API + 抓取 + directLLM |
| 竞品分析报告 | 800-2000 元/份 | 同上 + 产品信息抓取 |
| 商机雷达订阅 | 998 元/年 | 招投标/采购信息抓取 + 推送 |
| 出海参谋（高管咨询） | 万元级/单 | 人工 + AI 辅助 |

### 报告生成流程（线性管道，不需 Dify）

```
供求信息（输入）
  → ① 启信宝 API（工商/股权/风险/诉讼）→ 结构化数据
  → ② 供应商网站抓取（产品信息）→ 整理
  → ③ directLLM 生成两份报告：
       - 背景报告
       - 竞品分析报告
```

### 技术支撑（需新增）

| 组件 | 工作量 | 说明 |
|------|------|------|
| 启信宝 API 对接 | 1-2 天 | 外部 HTTP 调用，按次付费 |
| 网站抓取 | 先外部服务 | ScrapingBee 等，后自建 Puppeteer |
| directLLM 报告生成 | ✅ 已建好 | 复制 AIF 的 `directLLM.ts`，改 prompt |
| 报告模板 + 存储 | 2-3 天 | 结构化报告 + 缓存 |

### 为什么这阶段能赚钱

中国企业出海最大痛点是"不知道海外供应商/竞品靠不靠谱"。一份 AI 自动生成的背景报告，比企业自己雇人调研便宜 10 倍、快 10 倍。这是 AI 杠杆 + 30 万人才 know-how 的结合，**别人抄不走**。

## 四、阶段三：交易佣金（撮合，天花板最高但最后做）

| 收入 | 定价 | 技术 |
|------|------|------|
| 项目对接撮合佣金 | 成交额 0.5-1% | 匹配引擎 + 交易记录 |
| 顾问网络服务费 | 按小时/天 | 专家库 + 预约系统 |
| 海外本地化协助 | 按项目打包 | 本地人才匹配 |

### 技术支撑（需新增）

- 匹配引擎（SQL 确定性排序，0 资源）
- 交易/撮合记录 + 信用评分

### 为什么最后做

撮合佣金需要真实交易量，交易量需要平台先有足够的人和信任。这是"果"不是"因"。前两阶段做好了，这阶段自然来。

## 六、技术决策（重要，避免过度设计）

### 1. 不需要 Dify（现阶段）

ZTEIST 的 AI 需求是「匹配 + 聊天 + 报告」，不是「复杂多分支 workflow」。

| 需求 | 实现方式 | 本地资源 |
|------|------|------|
| 智能匹配 | SQL + 规则引擎 | 0 |
| 聊天/客服 | directLLM 直连 DeepSeek | 0（外部 API） |
| 报告生成 | directLLM + 启信宝 API + 抓取 | 0（外部） |
| 语义搜索（可选） | pgvector / sqlite-vss | 小 |

> Dify 只在出现「多模型节点 + 知识库 + 大量条件分支」的重流程时才值得上。AIF 的八字报告需要 Dify，因为它是 6 步复杂 workflow。ZTEIST 的报告是线性管道，代码就能写。

### 2. 服务器规格

| 场景 | 规格 | 月费 |
|------|------|------|
| MVP（会员费 + 聊天） | 2核2G + 40G | 50-100 元 |
| 加报告（外部抓取） | 2核2G | 50-100 元 |
| 加报告（自建抓取） | 4核4G + 60G | 200-400 元 |

> 真正吃资源的是**网页抓取**（Puppeteer 无头浏览器），不是 LLM 也不是编排。先用外部抓取服务，验证付费后再决定自建。

### 3. 复用 AIF 能力清单

| 能力 | 复用方式 |
|------|------|
| directLLM（DeepSeek 直连 + SSE） | ✅ 复制 `directLLM.ts`，改 prompt |
| 鉴权（邮箱验证码/Google OAuth） | ✅ 复用 |
| 邀请码系统 | ✅ 改成国家码 + 观察期 |
| 支付（Stripe + 微信/支付宝） | ✅ 双主体架构 |
| 多语言 i18n | ✅ 四语种现成 |

## 七、执行优先级

```
第一步（MVP，现在）：
  会员费 + 注册 + 搜索 + 邀请码 → 验证企业付费意愿

第二步（3-6 个月后）：
  企业背景报告 + 竞品分析 → AI 差异化高毛利

第三步（生态成熟后）：
  撮合佣金 + 顾问网络 → 交易变现
```

---

## 八、关键风险提示

1. **支付隔离**：AIF/ZTEIST 互不代收，否则 Stripe 冻结连带封号
2. **同机部署**：PM2 永远 reload 具体 app 名，禁止 `reload all`
3. **网页抓取合规**：供应商网站抓取注意 robots.txt 和版权，避免法律风险
4. **启信宝授权**：企业背景数据有合规要求，需用户授权才能查
